# Production-развёртывание

Эта инструкция описывает основной production-ready путь развёртывания Night Core V1.

[English version](../DEPLOYMENT.md)

## Требования

- PHP 8.1 или новее.
- PHP-расширения `pdo` и `pdo_mysql`.
- MariaDB/MySQL, доступная с хоста приложения.
- Отдельная база данных и отдельный пользователь БД без root-прав.
- Доступная для записи директория хранения уровней вне публичного document root.
- Веб-сервер, document root которого указывает на `public/`.

Не публикуйте корень репозитория как document root. `.env`, миграции, исходный код и runtime-данные не должны скачиваться по HTTP.

## 1. Настройка окружения

Скопируйте production-шаблон и замените все значения `CHANGE_ME`:

```bash
cp .env.production.example .env
chmod 600 .env
```

Важные production-правила:

- оставляйте `APP_DEBUG=0`;
- используйте отдельного пользователя БД вместо `root`;
- держите `LEVEL_STORAGE_PATH` вне `public/`;
- добавляйте в `CORE_ADMIN_ACCOUNT_IDS` только доверенные account ID администраторов;
- оставляйте `TRUST_PROXY_HEADERS=0`, пока origin не закрыт за доверенным reverse proxy;
- для Newgrounds оставляйте разумный timeout и negative-cache TTL, чтобы внешние запросы не блокировали PHP надолго.

## 2. Подготовка базы данных

Создайте отдельную базу и пользователя. Пользователю приложения нужны обычные права чтения/записи, а также права на изменение схемы, необходимые миграциям Night Core внутри этой базы. Глобальные привилегии не требуются.

Night Core не создаёт пользователя СУБД самостоятельно.

## 3. Установка Night Core

Выполните:

```bash
php bin/nightcore install
```

Команда:

1. проверяет наличие `.env`;
2. создаёт/проверяет директорию хранения уровней;
3. применяет все ещё не выполненные SQL-миграции в правильном порядке;
4. запускает deployment doctor;
5. завершает работу с ненулевым кодом, если критическая readiness-проверка не прошла.

Installer безопасно запускать повторно при обновлениях: уже применённые миграции пропускаются.

## 4. Структура веб-сервера

Document root сайта должен указывать на:

```text
/path/to/Night-CoreV1/public
```

Не указывайте его на `/path/to/Night-CoreV1`.

Хранилище уровней обычно лучше держать вне репозитория, например:

```text
/var/lib/nightcore/levels
```

Пользователю PHP/веб-сервера нужен доступ на запись в эту директорию, но не более широкие права на файловую систему, чем необходимо.

## 5. Health и readiness

Night Core предоставляет две операционные проверки:

- `/health.php` проверяет, что приложение загружается и может подключиться к БД;
- `/ready.php` дополнительно проверяет нужные PHP-расширения, основные таблицы, состояние миграций, доступность хранилища уровней и критические production-настройки.

Публичный readiness-ответ специально минимален:

```text
ready
```

или HTTP 503:

```text
not_ready
```

Подробности неудачных проверок записываются в error log сервера, а не отправляются клиенту.

Для отчёта оператору:

```bash
php bin/nightcore doctor
```

## 6. Cloudflare / reverse proxy

Когда перед Night Core установлен Cloudflare или другой доверенный reverse proxy:

1. по возможности запретите произвольным клиентам прямой доступ к origin;
2. ограничьте входящий трафик только используемым proxy/origin-маршрутом;
3. только после этого включайте `TRUST_PROXY_HEADERS=1`, когда нужны proxy-заголовки с IP клиента;
4. используйте TLS от клиента до proxy и, где возможно, от proxy до origin.

Не включайте доверие к proxy-заголовкам на origin, который доступен напрямую: иначе клиент сможет подделать forwarding headers.

## 7. Newgrounds

Для автоматической загрузки кастомных песен серверу нужен исходящий HTTPS-доступ. Основные параметры:

```env
NEWGROUNDS_FETCH_ENABLED=1
NEWGROUNDS_USE_BOOMLINGS_METADATA=1
NEWGROUNDS_DIRECT_FALLBACK=1
NEWGROUNDS_TIMEOUT_SECONDS=5
NEWGROUNDS_NEGATIVE_TTL_SECONDS=3600
```

Подробности: `docs/ru/NEWGROUNDS.md`.

## 8. Процедура обновления

Для каждого нового релиза:

```bash
# сначала обновите код приложения
php bin/nightcore migrate
php bin/nightcore doctor
```

Перед переключением реального GDPS-трафика убедитесь, что `/ready.php` отвечает HTTP 200. При изменениях протокола или схемы сначала проверяйте ревизию на staging/одноразовой БД настоящим клиентом Geometry Dash.

## Откат

Откат кода приложения и откат базы данных — разные операции. SQL-миграции сейчас forward-only, поэтому перед production-обновлением с новыми миграциями делайте резервную копию базы данных.
