# Центральный модуль веб-защиты

Браузерные панели Night Core используют единый слой `src/Web/Security/` вместо отдельных копий логики сессий, CSRF и HTTP-заголовков.

## Компоненты

- `PanelSecurity` запускает и проверяет сессии, меняет session ID, создаёт CSRF-токены и nonce для CSP.
- `SecurityHeaders` отправляет общую Content Security Policy и защитные заголовки браузера.
- `RepositoryAccountStateProvider` на каждом авторизованном запросе отклоняет неактивные, заблокированные и просроченные к удалению аккаунты.
- `PanelLoginThrottle` ограничивает повторные неудачные входы в staff/Event с подготовленными PDO-запросами и раздельными хешированными сетевыми идентификаторами.

Модуль используется в:

- `/dashboard.php`;
- `/staffAdmin.php`;
- `/eventAdmin.php`.

## Свойства сессий

У каждой панели своё имя PHP-сессии. Используются только cookie со следующими свойствами:

- `HttpOnly`;
- `SameSite=Strict`;
- `Secure`, если прямой запрос или доверенный proxy сообщает HTTPS;
- strict mode и отключённые session ID в URL;
- смена session ID после входа и выхода;
- отпечаток браузера на основе User-Agent;
- тайм-аут бездействия и абсолютный срок из `config2.php`.

При каждом авторизованном запросе дополнительно проверяется, что аккаунт существует, активен, не заблокирован, не достиг срока удаления и всё ещё имеет право на приватную панель.

Значение тайм-аута `0` отключает только соответствующий тайм-аут. Оно не отменяет проверку аккаунта, прав, браузера и ручной выход.

## Целостность запросов

Каждый изменяющий состояние запрос требует отдельный CSRF-токен панели. Токены создаются через `random_bytes()` и сравниваются через `hash_equals()`.

CSP использует новый nonce для script/style-блоков. Произвольные inline-script атрибуты запрещены через `script-src-attr 'none'`. Существующие атрибуты оформления пока разрешены через `style-src-attr 'unsafe-inline'`; это уже значительно уже, чем разрешение всех inline script/style-блоков.

Также отправляются запрет iframe, защита от MIME-sniffing, same-origin referrer policy, cross-origin ограничения, урезанный Permissions Policy и запрет кеширования. Staff/Event дополнительно получают `X-Robots-Tag`.

## Ограничение входов и сетевые идентификаторы

Ошибки входа Staff и Event записываются в `core_staff_admin_login_attempts`. В hash входит имя панели, поэтому идентификаторы разных панелей разделены.

Рекомендуемая production-настройка:

```env
PANEL_SECURITY_HASH_KEY=длинный_случайный_секрет_не_равный_паролю_базы
```

При наличии ключа используется HMAC-SHA256. Затем fallback — `REGISTRATION_IP_HASH_KEY`, а при отсутствии обоих ключей — необратимый SHA-256 hash. Исходные адреса модуль не хранит.

`TRUST_PROXY_HEADERS=1` допустим только за доверенным reverse proxy, когда origin закрыт firewall от прямого доступа. Иначе клиент сможет подделать forwarded-заголовки адреса или протокола.

## Граница защиты

Модуль защищает браузерные панели Night Core, но не заменяет:

- HTTPS;
- Cloudflare или другой reverse proxy;
- firewall origin-сервера;
- лимиты Nginx/Apache/PHP-FPM;
- ограничения доступа к базе;
- обновления ОС;
- резервные копии и реагирование на инциденты;
- DDoS-защиту.

Endpoint-ы протокола Geometry Dash продолжают использовать собственную авторизацию, валидацию и прикладные лимиты.
